# SEO/GEO audit — 2026-10-27

Fresh-perspective audit of tehisabiline.ee with no prior assumptions kept, run against the live site and the repository, then implemented in two releases. Everything below is either verified in the repository or taken from a primary source read on 2026-10-27; items that could not be verified are marked.

## Why the audit happened

Google ranked `/saidikaart/` (the HTML sitemap) on page 4 for "nis2 eesti" and showed **no** NIS2 content page; the site was absent from the top 20 for plain "nis2". The goal set by the owner: `/nis2/` first for "nis2 eesti", and at least second for "nis2".

## Method

Eight parallel read-only audits over the same extracted corpus (`/tmp/seoaudit/`): page text, HTML, headers, sitemap, llms files, JSON-LD, the script set, and the deploy set. Each audit had one lens:

| Audit | Lens |
|---|---|
| `audit-content-nis2`, `audit-content-core`, `audit-content-frameworks`, `audit-content-en` | content quality, intent match, overlap, information gain |
| `audit-fact-nis2`, `audit-fact-nis2-hub`, `audit-fact-dora-iso`, `audit-fact-cra-ai` | claim-by-claim verification against Riigi Teataja, EUR-Lex, RIA, FI, TTJA, EIS, IAF |
| `audit-schema` | JSON-LD vs visible content, entity structure |
| `audit-geo` | answer-engine retrieval: access, indexability, entity clarity, passage quality, freshness, corroboration |
| `audit-crawltech` | crawl, redirects, robots, headers, machine files |
| `audit-perf` | Core Web Vitals (no action recommended) |
| `audit-offsite`, `audit-schema`, `audit-serp-broad` | entity/off-site signals, brand SERP, query-level SERP sample |

Primary sources were fetched, not quoted from memory: Riigi Teataja KüTS (kehtiv redaktsioon 16.10.2026, RT I, 06.10.2026, 2), RIA notification and incident guides, EIS grant page (status checked 27.10.2026), EUR-Lex AI Act and CRA (through the page reader), AI Act Service Desk, IAF, EAK, the e-Business Register. google.com and bing.com SERPs were not scraped; SERP evidence came from the search tool and a 49-query sample.

## What hurt, and what changed

### Ranking blockers (Release 1)

1. **The HTML sitemap was competing with the guides.** `/saidikaart/` is now `noindex, follow` and is out of the sitemap, the entity map and the llms files. It stays linked from the footer because people use it.
2. **The NIS2 hub answered a different question than the query.** `/nis2/` was rewritten around "nis2 eesti": exact-match title and H1, an answer-first block, a KüTS §3 category-and-size table with worked examples, incident clocks, fine ceilings, registration route, EIS grant, and a change log with the law version. Word count went 3,461 → 3,187 while unique internal links went 22 → 24: shorter, denser, and no `nis2.ee` citations.
3. **The navigation hid the topic.** The header item is now "NIS2 Eestis" and the footer is a grouped, locale-aware footer (about column + four link groups, 34 links instead of 53) that no longer dumps every URL on every page.
4. **Internal authority was spread over 53 footer links.** The gate now requires the 15 primary hubs to be one click from the home page and every indexable page to be reachable within two clicks, instead of requiring the home page to link all 58 URLs.
5. **The home page had no NIS2 entry point.** It now opens the deadline section with NIS2, lists it first, and answers "Kas NIS2 mind puudutab?" with the actual size test instead of "probably not".

## What was missing, and was added

- **Date integrity tooling.** `tools/stamp-modified.mjs` makes the visible page date the single source and copies it to `dateModified`, `article:modified_time`, the footer and the sitemap; `--check` fails the build on drift. It replaced a rule that was violated on 18 pages.
- **FAQ parity.** `tools/sync-faq.mjs` and a new gate check keep JSON-LD answers byte-identical to the visible answer; 15 answers had drifted.
- **Breadcrumb parity.** The gate now compares the visible trail with `BreadcrumbList` names, URLs and order. `/sektorid/energeetika/` claimed "Sektorid" while linking to itself.
- **Guards that encode lessons learned:** no `nis2.ee` link or citation, and no "31 March 2026" as a statutory date, in any page.
- **Entity corrections:** the F6S profile moved off `Person.sameAs` (it is a company profile), and `Organization.address` now carries the true municipality instead of Tallinn.
- **Machine files:** `llms.txt` and `llms-full.txt` corrected (seat, AI Act dates, NIS2 clocks, E-ITS/ISO claims, hardware status), `entitymap.json` and `humans.txt` marked `noindex` at the edge.
- **Downloads:** the regulations CSV actually parses now (8 fields per row; it had 9–10 because of semicolons inside values), the deadlines ICS is RFC-5545 valid (CRLF, 7 events, unique UIDs) and distinguishes 2 Aug from 2 Dec 2026, the NIS2 evidence workbook and checklist PDF were regenerated from one source list.

## Deliberately not done

- **Publishing prices.** Competitors publish ranges (`alates 2000 €`); ours says the price depends on scope. Publishing a range is an owner decision, not an SEO fix.
- **The English consolidation** (nine overlapping EN spokes → hubs). The English pages are the ones that currently appear in search results; redirecting them before any click data exists risks the only visibility the site has. Revisit when Search Console shows which English URLs earn impressions.
- **Removing `FAQPage` or `Service` markup wholesale.** FAQ rich results are no longer shown by Google, but the markup is accurate, costs nothing to keep and serves other consumers; the gate now guarantees it matches the page.
- **Performance work.** The performance audit found nothing worth the effort.
- **No new "what is X" pages.** The hub-and-spoke map is already complete; more synonym pages would be doorway content.

## False positives worth recording

The e-Business Register page contains a hidden deletion-notice template (`<div class="card d-none company_warning_notices">`) that is displayed only when the announcements API returns rows. Two audits read it as an active notice. The API (`at_proceedings_json`) returns zero rows for registry code 17607255, and the register status is "Entered into the register" with no tax debt as of 2026-10-27. No deletion process is visible.

## Owner-gated (not done here)

1. **Search Console**: sign in at the shared desktop and request indexing for `/nis2/` and the NIS2 spokes. Until then index status is unknown (the last snapshot showed one indexed URL and 3 clicks / 20 impressions).
2. **Bing Webmaster Tools**: submit the sitemap; IndexNow is scripted but nothing proves submission history.
3. **Backlinks**: the only referring domains are self-published profiles. The realistic routes are the NIS2 checklist PDF and the evidence workbook offered to ITL, EISA, Startup Estonia, Tehnopol and Finance Estonia, and a comment/quote to the Estonian security press. Playbook: `docs/seo/backlink-playbook.md`.
4. **Domain mail**: no MX, SPF or DMARC on the domain; a company that answers "write to us" from a Gmail address loses a trust signal and can have its sender domain spoofed.
5. **Entity identity**: decide whether to publish a full street address (the register shows the Viimsi registered office) or keep the municipality-level statement; create the LinkedIn company page; correct the F6S description, which currently contradicts the compliance positioning.
6. **Cloudflare**: check WAF/bot rules and cache behaviour from the dashboard — not observable from outside.
7. **Google Ads**: the only measure that can put `/nis2/` on top within days, independent of the organic work.

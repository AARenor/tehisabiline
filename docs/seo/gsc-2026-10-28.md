## What changed

1. `/nis2/` — section H2 is now `NIS2 nõuded: kümme riskijuhtimise meedet (art 21 lg 2)`, plus one body sentence and the FAQ question `Millised on NIS2 nõuded?` (visible text and FAQPage JSON-LD both). TOC label matches.
2. `/cra/` — title, `og:title`, `twitter:title`, og-image alt and WebPage `name` now `Cyber Resilience Act (CRA) Eestis: nõuded ja tähtajad`; description opens with `Cyber Resilience Act (CRA) määrus eesti keeles`. H1 already carried the full name.
3. `/en/cra/` — title `Cyber Resilience Act (CRA) in Estonia: Scope, Reporting`, description and OG/Twitter mirror.
4. `/ai/` redirect destination chain unchanged (arle.top owns the AI cluster). arle.top got the content instead: `/ai-arendus/` and `/en/ai-arendus/` carry a new `AI teadmistebaas` section (what goes in, what stays out, how it is measured) and a matching FAQ in visible markup and FAQPage JSON-LD; the root offer card for "AI-assistent meeskonnale" now names the knowledge base.
5. Sitemap `lastmod` for both CRA URLs moved to 2026-10-28 to match `dateModified` (`npm run test:seo` enforces this).
6. IndexNow: 3 tehisabiline URLs and all 30 arle.top URLs submitted (Bing/Yandex/Seznam). Google ignores IndexNow.

## Indexation state

`gsc_inspect.py` on `/cra/`, `/en/cra/`, `/kasutusjuhud/`, `/nis2/audit/`, `/en/nis2/audit/`: all `PASS`, "Submitted and indexed", robots `ALLOWED`, Google-selected canonical equals declared, last crawl 24–27 Oct.

arle.top: `/`, `/ai-arendus/`, `/ai-chatbot/`, `/ai-automatiseerimine/`, `/ai-agent/`, `/ai-konsultatsioon/`, `/tarkvara-arendus/` indexed (crawl 26–27 Oct). `/en/`, `/en/ai-arendus/`, `/artiklid/mis-on-ai-agent/` = "URL is unknown to Google".

Cause: GSC last downloaded `https://arle.top/sitemap.xml` on 26 Oct 11:04 and recorded 7 submitted URLs; the file on disk now lists 30. Re-submitting through the API is blocked — the ADC token only carries `webmasters.readonly`, and `PUT /sitemaps/...` returns `403 ACCESS_TOKEN_SCOPE_INSUFFICIENT`. The EN URLs are reachable from the ET pages (hreflang plus the `ET | EN` switch) and are in the sitemap, so this is a wait-for-recrawl item, not a code defect. A `gcloud auth application-default login --scopes=https://www.googleapis.com/auth/webmasters` would unblock API sitemap submission.
